# Как собрать диагностику звонка

После одной неудачной попытки на каждом телефоне открыть Профиль → Диагностика звонков и сохранить/передать JSON через системное меню. Отчёты сопоставляются по callId, UTC-времени, платформе, сборке и session запуска. Автоматической отправки отчёта нет.

В формате schema 2 сохраняются 400 последних технических событий: seq, попытка, экземпляр RTC-движка, HTTP-статус/длительность, SDK-соединение/микрофон/подписка на аудио, причина end/reset/leave. Полная карта числовых causes включена в файл. Имена, адреса, сообщения, голос, параметры канала и токены исключены; повреждённое хранилище не ломает экспорт.

Коды причины: 1 — пользователь завершил; 2 — отклонил; 3/4 — тайм-аут входящего/исходящего; 5/6 — peer offline/RTC failure; 7/8 — initiate/accept failure; 9/10 — WebSocket/push окончания; 11 — API уже закончил вызов; 12/13 — CallKit end/timeout; 14 — Android native end; 15/16 — logout/unmount; 17/18 — замена движка/локальный reset; 19/20 — опоздавший HTTP-ответ; 30 — микрофон запрещён; 31 — занято.

Только запросы действий звонка дополнены заголовками X-Empin-Build, X-Empin-Platform, X-Empin-Call-Session и X-Empin-Call-Cause. Сервер их очищает и связывает с ID авторизованной сессии в отдельном локальном журнале. Причина от клиента служит диагностикой и не участвует в авторизации.

Номер сборки в отчёте обязателен при разборе. Успешный HTTP accept или RTC join не доказывает наличие голоса: проверить события обоих участников и фактическую слышимость. Базовая диагностика iOS 17 / Android 24 не содержит полного schema 2; расширенные события требуют следующей сборки из текущего коммита.
